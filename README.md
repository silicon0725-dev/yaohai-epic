# 体素地形内核 — Stage E（性能与资源体系）

Godot 4 体素沙盒游戏的技术原型，开发文档（`docs/DEVELOPMENT_PLAN.md`）
的 **阶段 A-E 全部完成**：静态地形 -> 交互 -> 流式加载 -> 增量存档 ->
基准测试与真实材质包。水平无限世界，15 种方块（含静止水），Conquest 写实材质包，
Greedy Meshing 可切换。物品层 v1（背包/工具/合成）之上接入
**地面掉落实体**：挖掘产物落地成实体，走近自动拾取，随存档持久化。
**水系统**：海平面海洋、半透明独立水面、玩家游泳、掉落物浮沉、
MC 式水位流动/扩散（挖沟引水、拆坝放水、断供回退）。

## 引擎版本锁定

- **Godot 4.7.2.stable.mono.official**（官网构建，安装于 `~/godot/godot`；
  早期使用的 snap 包 `godot-4` 缺少 .NET 数据通道，已弃用）
- 脚本语言：GDScript + C#（Greedy 网格器走 C# 原生路径，见"网格管线 C# 迁移"一节）
- **C# 运行前提**：系统 .NET SDK（本项目面向 net8.0，`voxel-terrain.csproj`
  设置了 `RollForward=LatestMajor`，仅有 .NET 9/10 运行时的机器也能跑）。
  修改 `native/NativeMesher.cs` 后需 `dotnet build voxel-terrain.csproj`
- **渲染器**：项目锁定 `gl_compatibility`。本机 GT 610（Fermi）无 Vulkan
  支持，llvmpipe 软渲染的 Vulkan JIT 会生成 BMI2 指令（本机 2014 年
  赛扬不支持），导致 SIGILL 崩溃；OpenGL 4.3 走这块卡硬件加速，稳定。

### 操作（第一人称玩家）

- `WASD` 移动，`Space` 跳跃，`Shift` 疾跑；**入水后 Space 转为上浮**，
  水中移速打六折、重力减弱缓沉（游泳），潜到水下全屏泛蓝
- **掉落物浮沉**：木头系（原木/木板/木棍/木镐）落水漂浮上浮，
  泥土石块等重物缓慢下沉
- 鼠标左键点击窗口锁定视角，`Esc` 释放
- `按住左键` 挖掘（时长由方块硬度与手持工具决定，准星下有进度条；
  基岩不可破坏），`右键` 放置（消耗手持方块物品）
- **挖掘产物落地为实体**：走近（1 格内）自动拾取入包；背包满则
  掉落留在地面，腾出空间后拾取；同类掉落落地后互相合并
- `1-9, 0` 数字键或 `滚轮` 切换热栏（背包前 12 格），`E` 开关背包界面
  （点击拿起/放下/交换/合并堆；左侧合成面板点击配方行合成，材料
  不足整行置灰；关背包时手中还有堆会丢到身边地面）
- `Q` 朝视线方向抛出 1 个手持物品，`Ctrl+Q` 抛出整堆（1 秒保护期内
  不能被拾取，防止扔出瞬间又捡回）
- 升级闭环：砍原木→合成木板/木棍→木镐→挖石得圆石→石镐
- 新世界起始装备：木镐 + 泥土×16 + 木板×16；石头系需要镐才掉落物品
- 挖穿悬空岛边缘掉落后自动回到出生点
- 修改每 10 秒自动保存，退出时全量保存（含背包）；重启游戏世界原样恢复

- **背包**：`items/inventory.gd`，24 格（前 12 格即快捷栏），堆叠并入/

- **挖掘规则**：方块定义新增 `hardness`（徒手秒数，基岩 -1）与
  `requires_tool`（class + min_tier）。`BlockMining.break_info` 综合

  准星下进度条可视化
- **掉落表**：`items/drop_table.gd`，草→泥土、石头→圆石、煤矿→煤、
  其余掉自身；产物经地面掉落实体落地拾取（见下一节）
- **表现层**：`presentation/item_icons.gd`——方块物品从图集裁剪 side
  贴图（材质包替换自动跟随），材料/工具程序化像素画；HUD 快捷栏
  （图标+数量+选中框）、E 键背包界面（点击拿起/放下/交换）
- **存档**：背包随 player_state 序列化（稳定名称，未知名称跳过、
  超上限截断）；旧档无 inventory 键自动补发起始装备（木镐+泥土×16+
  木板×16）——已在真实旧档上验证
- **合成系统**（`items/crafting_recipes.gd`）：v1 无序配方（材料计数
  匹配即合成，无网格摆放），原子性由 craft() 保证（先校验后消耗再
  产出，失败零副作用）。配方链 4 条构成工具升级闭环：
  原木→4 木板；2 木板→4 木棍；3 木板+2 木棍→木镐；
  3 圆石+2 木棍→石镐（挖石得圆石闭环，与 MC 一致需 2 根原木起步）。
  背包界面左侧合成面板：材料不足整行置灰，点击合成一次，
  `inventory.changed` 驱动实时刷新。`Inventory.remove_item` 支持跨堆
  消耗（从末尾堆向前扣）
- **检查**：`tests/test_items.gd` 73 项 + `tests/test_crafting.gd` 63 项
  （配方定义/原子合成/跨堆消耗/升级闭环/背包满丢弃语义）；
  `debug/items_ui_check.tscn` headless 断言 HUD 几何与接线（快捷栏

## 地面掉落实体（物品层扩展 v1.1）

挖掘产物不再直接入包，而是生成世界内实体，延续数据/规则/表现分离：

- **规则层**：`items/item_drop.gd`（RefCounted，纯数据+物理，可 headless
  单测）。体素网格上的简化点碰撞（不依赖引擎物理服务器）：逐轴移动前
  探测目标四角格是否实心，撞墙清速度、落地吸附格顶、被方块掩埋时逐帧
  上浮逃出；y<0 实心（与网格边界策略一致）、世界顶以上空气、未加载
  区块按空气。拾取半径（水平 1.0 / 垂直 1.25）、出生保护期、
  5 分钟活跃时间消散、序列化（稳定名称）都在此层。
  **无磁吸**（MC/BDIR 均无此机制）：磁吸会把落定物品拉离地面卡在
  坡上，表现为"以随机倾角插进地里"（Q 投掷复现确认），已移除
- **生命周期/表现层**：`items/drop_manager.gd`（Node3D）。所在区块
  非 ACTIVE 即冻结（与玩家同一门禁，冻结期间 age 不推进——远离玩家
  的掉落不会场外消散）；每 0.5s 合并近距离同类堆（遵守 max_stack）；
  拾取入包用 `Inventory.can_fit` 预判——满包不拾取，
  部分装下时余量留在掉落里；实体上限 128，超出 spawn 拒绝、调用方
  （玩家控制器）回退旧语义直接入包。表现：每实体一个 Sprite3D
  广告牌（32px 图标 ×0.012 ≈ 0.38 格），方块物品满幅（MC 式平面
  方块）、像素画物品纯色背景转透明（`ItemIcons.world_sprite_for`），
  竖直浮动动画相位随物品 ID 错开
- **接入**：玩家 `_break_block` 把 DropTable 产物散射生成（方块中心 +
  随机小初速）；关背包时手中剩余堆丢到身边地面（保护期 1s）。
  **Q 丢弃**：`_drop_held`（Q 单件 / Ctrl+Q 整堆）从眼睛沿视线抛出
  （速度 5.0 + 上抛 1.2，保护期 1s 防瞬吸回）。`Inventory.add`
  语义不变——它总会开新堆，只有整包无空间才留余量
- **存档**：掉落实体随 `world.json` 持久化（新键 "drops"，经
  `ChunkManager.extra_meta_provider` 注入 `WorldSave.save_meta` 的
  extra 参数；保留键冲突拒绝）。物品/数量/位置/速度/年龄/保护期全量
  保存，读档原位恢复；未知物品跳过、超堆截断、超 128 截断。旧档无
  该键即无掉落，完全兼容
- **检查**：`tests/test_drops.gd` 139 项（物理落点精确断言/撞墙/掩埋
  逃出/冻结门禁/自旋推进与落地冻结/拾取半径与无磁吸回归锚点/满包与部分
  入包/合并/消散/序列化容错/world.json 扩展键保护/姿态四元数、
  副本重建与不嵌地、贴地支撑半径、挤出网格、触地补间、台阶落定
  与贴墙停驻）；`debug/drops_check.tscn` headless 集成检查 22 项
  （挖掘->落地->自动拾取->远处保留->Q/Ctrl+Q 丢弃->重启恢复全链路）；
  `debug/capture_drops.tscn` 在程序化台阶地形上出截图，另以自然
  地形批量撒落（60 个随机速度/堆量）核验零嵌地、姿态全部落定

### 掉落表现（模仿 Better Dropped Items Renewed）

视觉规则模仿 Minecraft 模组 Better Dropped Items Renewed 1.2.1
（Fabric，反编译核对行为后复刻，MIT 许可）：

- **方块物品 = 3D 迷你方块**（`presentation/drop_visuals.gd`：0.25 格
  立方体，六面图集贴图，复用地形网格器的面表/UV/绕序约定）；
  **材料/工具 = 挤出厚度的像素模型**（每个不透明像素一个小方柱，
  MC 2D 物品"厚贴图"观感；轮廓侧边才生成侧面，网格按物品缓存）。
  两类**共用同一套姿态管线**（触地补间/支撑半径/碰撞足迹），空中
  姿态与落地角度按 Mod 分类：方块空中翻滚（pivotX(-90°)+pivotZ
  链）、落地补间到端正竖立（底面贴地、竖直 90°、保留偏航）；平面
  物品空中站立绕 Y 旋转（Mod 的 2D 行为，不翻滚）、落地补间纯 90°
  翻倒到**平躺贴地**（面朝上 + 偏航，支撑半径只剩半厚度）——翻倒
  弧线的竖直跨度单调收缩，支撑线性插值即精确值，落地动画全程不会
  插进地面（曾把空中也统一成翻滚，slerp 到平躺的中间姿态不可控，
  落地瞬间会以随机角度铲进地面）；不接收阴影避免背光剪影
- **无悬浮 bob**：物品贴地而非飘浮（Mod 同样移除了 vanilla 悬浮）
- **碰撞按 MC 语义拆分两套半径**（`ItemDrop.footprint_radius` /
  `support_radius`）：横向阻挡 = 视觉对角（count>1 加散布余量），
  移动探测 + 每帧静止推出兜底（出生点贴墙/台阶沿的最小穿透轴推出）
  共同保证视觉不插进墙体；竖直支撑 = 视觉半宽小盒，只认"实心且
  其上为空气"的真表面——**旁边的墙永远不会被当成落脚面**
  （曾表现为堆叠物落到墙角后自动跳到上方一格，`capture_corner`
  场景断言回归）
- **count > 1**：默认散布若干随机偏移的小模型（Mod 默认，封顶 5 个）。
  副本偏移按姿态坐标系计算且不嵌地：3D 水平 ±0.15、竖直只向上；
  2D 在躺平坐标系的水平面散布并沿局部 -z（躺平后的世界向上）逐层
  抬升，不加倾角（倾斜的薄板会铲进地里）；
  `NEAT_STACKING` 开关可切平面物品竖直叠成一摞（Mod 可选项，默认关）
- 自旋角速度 1.0 rad/s = Mod 默认转速 100/100；每实体随机相位
  （对应 Mod 复用的 vanilla bobOffset）；副本偏移用按掉落身份确定性
  播种的随机源（帧间稳定、存档可复现）
- 姿态（自旋角/相位）随掉落序列化，旧档（v1 无该键）缺省 0 兼容

## 地形生成 v3（参考 Terrain Diffusion 移植）

参考 [Terrain Diffusion](https://github.com/xandergos/terrain-diffusion)
（扩散模型地形生成，"Perlin 噪声的实用继任者"）的**合成地形配方**
（`inference/synthetic_map.py`：纯 Perlin fBm + 统计变换逼近真实地貌）
移植三件套，扩散模型本身不引入：

- **分位匹配**（`transform_perlin`/`build_quantiles`）：把大陆 fBm 的
  输出分布重映射到真实测高曲线形状——大面积平原 + 长尾山地。
  源分位节点在生成器初始化时对本种子噪声固定采样校准（确定性），
  目标分位表 17 节点硬编码
- **粗图布局**（coarse map 条件生成）：低频山脉掩码决定山在哪里
  （smoothstep 门控），掩码内叠加脊状分形（RIDGED）生成山脊线；
  温度/降水两张低频粗图 + 温度随海拔递减率（lapse）选生物群系：
  荒漠（热且干的低地）/ 草原 / 裸岩山地 / 滩涂沙地
- 矿物生成沿用 v2 语义；固定种子确定性不变；每列 6 张噪声场
  （大陆 4 倍频/山脉/山脊/细节/温度/降水），生成耗时约
  4.4ms/区块（同步实测），流式工作线程预算内

## 水系统（参考 Realistic Environments 的分层思路；流动为 v2）

参考 [Godot RealisticEnvironments](https://github.com/Alexofsunny/Godot-RealisticEnvironments)
（FFT 波谱海洋模拟）取其**分层思想**——水是独立的渲染通道与物理域，
不与固体地形混排；FFT 波浪本身不引入（体素静止水，后续版本边界）。

- **方块与生成（v4）**：`core:water`（ID 14，追加在注册表末尾不重排）。
  生成器版本升 4，海平面 `SEA_LEVEL = 7`：地表高度低于海平面的柱，
  从地表顶到海平面整段填水。出生点改为螺旋找陆地列，避免落水
- **网格与渲染（§6.5 透明通道独立）**：水不进不透明网格。面剔除与
  Greedy 两个网格器共用 `ChunkMesher.append_water_faces`：水仅在
  邻格为空气时出面（水-水内部剔除、水-固体不出面）。
  **连续水面（角点 max 模型）**：顶点高度 = 共享该角点的 2x2 四格
  中所有水格顶高的最大值（上方有水=满格 1.0，否则按级别
  surface_height），相邻水面在共享边角点同高 -> 顶面连续折面
  （斜坡衔接而非一格一层的台阶断崖）、侧面成梯形，级别差的竖缝
  由 max 天然封住；水位表合并 27 邻域（世界坐标）支持跨界角点。
  水分两个透明通道：顶/底面双面材质（潜水视角从下往上看得到
  水面），四侧背面剔除材质（下落水柱四面都朝空气，双面会把远侧
  背面也渲染出来，半透明叠成"浮空背面"——只出近面）。
  **水面波——Physics Mod 整合**（用户提供的 physics-mod-pro v188i
  jar；`presentation/ocean_waves.gd` + `water_surface.gdshader`/
  `water_side.gdshader` + `world/water_ripples.gd`）。无需反编译：
  mod 的方法全在明文 shader 里，两件套逐条移植——
  - **真实起伏（言波）**：mod 的 ocean_legacy.glsl 迭代言波——
    13 次循环 Gerstner 风格分形波，波形 exp(sin-1) 非对称尖峰宽谷
    + 位置被波拖拽的水平位移（波峰翻卷感），每级频率 x1.18/速度
    x1.07/权重 x0.8、方向转 12°。GPU（顶点位移+差分法线+白沫+高光）
    与 CPU（`OceanWaves.wave_height`，掉落物浮到目标位随波起伏）
    **逐行同式**，波时钟统一（main 推进 global_time 同步 shader
    u_time，内置 TIME 与 CPU 毫秒不同基准会相位漂移）。
    **XZ_SCALE 用 0.10 而非 mod 原值 0.035**：原值波长约 30 格，
    ±0.25 格振幅摊上去坡度仅 5%，视觉上就是一块平面（曾因此被
    误判为顶点位移未生效——岸线两帧对比 12000+ 水陆转换像素证明
    位移一直在跑）；0.10 -> 波长约 10.5 格、坡度 15%，相邻格顶点
    高差约 0.3 格，肉眼可见的涌浪；
  - **岸距衰减（mod 的 waviness 思路，用户验收修正"岸边水起伏
    不得穿岸块"）**：网格器统计每水格**同层+y+1 层的 8 邻固体数**
    得格级衰减（任何固体邻 -> 0.15，开阔 1.0），**按顶点（角点）
    2x2 四格平均插值后**烘进 COLOR.r——水面网格相邻格不共享顶点，
    按格常量衰减会让同一边界位置的顶点各乘各的衰减值，波浪把同
    位置顶点抬到不同高度产生**裂缝**（用户发现的"岸边浪与远岸浪
    分开"）。角点衰减**只依赖角点自身 2x2 四格（同层+y+1 层）的
    固体性**——数据全在单圈 padded 内，跨区块边界的角点两侧区块
    必然算出同值（曾用格级衰减场按角点平均，两侧参与的格集不同
    -> 区块边界直线裂缝，用户第二轮验收发现）。shader 用它缩放
    波幅位移与法线扰动（位移再钳制 [-0.08, +0.22] 上涌为主）；
    ItemDrop 波高采样同公式。验证：侧视水线波动 118px -> 1px、
    长直线亮缝 0、波浪闪现 0
  - **齐平沙洲压平（生成 v5，用户报告"网格缺口"的另一半根因）**：
    height == SEA_LEVEL 的柱顶面恰在海平面上 0.125 格——贴水视角
    是大片**无水干沙色平台带**+同高露头横线，波浪让边界闪现，
    被视为水面缺口。v5 在 column_profile 里压低 1 格沉为 1 格
    水深浅滩（海滩线从 SEA_LEVEL+1 开始）。验证：贴水平视干沙
    色像素 13% -> 0%，波浪闪现 18 -> 3
  - **互动涟漪（波动方程）**：mod 的 ocean_ripple_simulate.fsh——
    高度场有限差分 `new = (cur*2-prev)·阻尼 + 拉普拉斯·传播 + 冲量`。
    gl_compatibility 无浮点渲染目标，改 **CPU 数组模拟**
    （`WaterRipples`：96x96 高度场 + ImageTexture 上传，方法/参数
    不变）；玩家（水中移动/落水冲击）与掉落物（水中漂流）注入
    圆斑冲量；模拟窗口 16 格跟随玩家（平移重采样）；水面 shader
    解码采样叠加顶点位移（**0.35 格可见的环形波**——mod 原语义
    0.01 级位移在我们无折射/反射的着色下不可见）与法线扰动。坑：
    边缘衰减封顶值写错成 1.0 会让全场每步乘 1/6（能量 8 步暴毙
    百万倍），封顶必须是衰减宽度本身
  - 保留：太阳反光（Blinn-Phong）、菲涅尔、浪尖白沫；RE 频谱表
    （wave_spectrum_cpu.gd）保留为备用
  - **ocean3d_lite 整合（用户安装的插件，采纳其二）**：
    - `OceanWaves.storm_scale` 全局海况缩放：一个变量同时放大
      CPU 物理采样与 shader 位移（main 每帧同步 uniform），
      1.0 平静 ~2.5 风暴，天气系统接这里；
    - **深浅双色按菲涅尔混色**（deep/shallow_color）：近处深蓝、
      掠射远处混向浅亮色，比单色+提亮更有层次（实测近远色差
      211）。浮物多探针浮力/表面速度阻尼未搬（我们的小物品
      直接跟随已天然骑浪，大船体才需要）。
  - **水面贴图层（用户要求"模型水 + 贴图"，参考 Effective/wakes）**：
    `assets/textures/water_still.png`（程序生成的 32x32 体素手绘
    风水纹，Conquest 像素风），shader 里**两层不同方向/速度**的
    世界坐标滚动采样叠加（MC water_still 动画的经典流动做法），
    白沫颗粒感也由贴图第二层调制；NEAREST 采样 + repeat（体素
    颗粒感），纹理由 `create_water_material` 自动加载
  纯视觉部分不改水位物理。**掉落物-波浪/涟漪互动**：
  - 浮物**随波起伏**：目标位 = 实际水位 + `OceanWaves.wave_offset`
    （振幅 0.4/钳制 [-0.08,+0.22] 与 shader 完全一致的统一入口）
    × 岸距衰减 − 半浸深度，弹簧式跟随（增益 3.0/s、速度上限
    0.9 格/s——早期"到位刹停"跟随仅 0.05 格/s 跟不上 ~0.4 格/s
    的波形，物品贴平均水位不动）；目标钳制表面格顶防顶出震荡
  - **入水冲击**：从空中落水（下落 >1.5 格/s）置 splash_pending，
    涟漪按落速注入大水花（强度 0.3-0.9、半径 0.9）
  - **漂流尾迹**：水中水平移动 >0.3 格/s 才注入弱冲量（静止
    漂浮物不持续扰动水面）
  定量验证：浮物 10 秒波幅 >0.15 格（跟住波形非静止）、落水
  置位 splash_pending、水中起步不置位；涟漪单测验证冲量起波、
  传播到 3 格外、能量随阻尼衰减。
  - 顶点起伏 + fragment 数值差分求法线（位移是位置的纯函数，
    顶面/侧面共享角点同位移，接缝不裂）；
  - **太阳反光**：法线与半程向量 Blinn-Phong 高光（多波随机相位
    使波光细碎弥散），太阳方向由场景 DirectionalLight 传入；
  - **菲涅尔**：掠射角水面更亮更实；
  - **浪尖白沫**：波峰阈值混入破碎白噪；
  - 像素波纹：量化世界坐标的移动亮度色块。
  纯视觉，水位/浮力物理不受影响（RE 的折射/焦散/平面反射/
  波高物理联动未搬——需要 depth prepass 与 RD compute，边界）。
  定量验证：两帧对比水面区 15% 像素流动、地形区变化 100% 属于
  水面/岸线（地形静止）、波光细碎弥散。
  **受光照渲染（用户指出"水怪是光照系统问题"）**：水面从 v1 起
  一直是 UNSHADED（纯色时代的防过曝选择），与受光地形的光照语言
  不一致（阴影投到水上水不变暗）。现改为受光：差分法线喂给场景
  光照（**波峰亮波谷暗的真实 shading**，不再靠颜色伪造）、接收
  岸边阴影、ROUGHNESS 0.12 低粗糙 specular；波光耀斑走 EMISSION
  （不被场景光二次调制）；基色高饱和补偿白光稀释（受光白光会
  拉灰，B-R 差从 60 掉 20，调饱和后回到 77）。
  `MeshBuilder` 组装多表面 Mesh，水面用独立半透明材质
  （UNSHADED 纯色 + ALPHA 0.68 + 双面：光照会把纯色水面推到近白
  再被 FILMIC 去饱和，关掉光照响应后深浅完全由透出的海底决定——
  浅滩亮、深水蓝）。C# 原生 Greedy 路径不认识水方块，含水区块
  自动回退 GDScript 路径补水面通道
- **交互**：体素射线穿过水（`is_targetable` 排除水），只能选中
  水下固体；对着水放置视水为可替换格（水中建筑）
- **玩家涉水/游泳两级判定**（MC 语义，基于实际水位
  `WaterFlow.water_surface_at`：向上扫表面格 + 级别高度，与掉落物
  浮力目标共用）：
  - **涉水（浸深 > 0.1）**：移速打六折——踩进一格深的浅滩走路
    变慢，但保持正常重力与跳跃（能跳出浅滩，Space 是跳不是上浮）。
    玩家不会被水流冲走（用户决策；掉落物仍会被冲走）；
  - **深水（浸深 > 0.9）**：才切换游泳物理（弱重力缓沉、
    Space `move_toward` 上浮；瀑布下落段向下带，按住 Space 挣脱）。
    0.9 取在源水 0.875 与整格 1.0 之间，贴格边界抖动不闪断；流动的水把玩家漂向下游（速度偏置式
  `CURRENT_DRIFT_SPEED`，逆流游泳被抵消；瀑布下落段向下带，按住
  Space 可挣脱），静止水（源/池内部）不推；相机格为水时全屏叠加
  半透明蓝色 ColorRect
- **掉落物浮沉与漂流**：`ItemDrop` 水中独立物理（弱重力/强阻尼/
  低终端速度）。木头系物品（原木/木板/木棍/木镐）浮到**所在水体
  的实际水位**（向上扫到表面格 + `water_surface_height(level)`，
  流动级别低 -> 水面矮）下方 0.12 处刹停稳定贴面（修冒出水面被
  拉回造成的快速上下震荡）；重物缓沉。水中水平移动带四角碰撞。
  流向查询 `WaterFlow.flow_direction_at`（静态纯函数，掉落物用；
  玩家不再被水流推动）：下方空气 -> 竖直向下（瀑布段）；否则水平朝"级别更大"
  的下游邻格（级别随离源距离递增，更大 = 地势更低；下落柱 8 是
  汇入点，物品漂向柱并随之坠下——曾写反成朝源方向，掉落物往
  高处漂）；流动水最远端查落差边（被冲到台阶边后落下，仅对
  level >= 1 生效——源是静水，一格宽源水柱的边缘不该有假流向）；
  源/平级静水零向量。流动的水沿流向把掉落物冲向下游（加速度 6、
  水平封顶 1.6），漂入静水区自然停驻；沉物落到水底固体顶面
  吸附停住（无此判定会"沉入固体 -> 掩埋逃逸顶回 -> 再沉"抽搐）
- **流动/扩散（v2，`world/water_flow.gd`）**：MC 式水位元胞自动机，
  水位存方块状态 `"level"`（§4.3 随存档持久化）：无状态 = 0 = 源
  （海洋填充，永久不退）；1..7 流动衰减（离源越远级别越大、
  水面高度越低，相邻共享角点连成斜坡，扩散半径 7 格）；8 = 下落水柱（满格
  渲染，落地后按 1 级重新扩散，可沿山坡一路流下）。规则每格每
  tick（0.25s）：先向下流、后水平扩散；扩散带寻坡（4 格内最近
  落差定向流，平地才四向铺开）；断供回退只降不升（拆掉源头后
  从边缘逐层剥落，防止水池互相供给不消退）。扰动由
  `VoxelWorld.block_changed` 信号驱动（挖掘/放置/水自身写入）。
  **性能（防掉帧）**：水写入 `affects_collision=false`——水没有
  碰撞体，跳过整区块 ConcavePolygonShape3D 顶点汤重建（掉帧
  主因），提交时按 collision_dirty 决定是否重建碰撞；单 tick
  上限 512 格 + 稳定水体短路（4 邻无空气不寻坡）。实测山顶
  放水沿坡流下数百格：FPS 均值 81 / 最低 64。演示：
  `res://debug/capture_water_flow.tscn`（山顶石碗拆壁放水，
  输出前后对比截图与级别分布统计）
- **边界**：水不可收集/不可放置、无波浪动画；未加载区块边界
  的水不主动流入新加载区域（流动水永不为源——挖渠引海水得到
  的是流动水，成不了无限水源，MC 的"双源成源"未实现）

## 动态树 v2（结构化树系统，参考 Dynamic Trees 技术方案重写）

v1（信号生长+体素网格枝干）经多轮迭代效果不佳后**按结构化方案重写**。
核心原则：**结构数据是权威状态，网格只是表现**。

- **数据层**（`systems/trees/`）：
  - `TreeSpecies`（Resource）：树种参数（高度/枝层/叶冠/方块绑定）
  - `TreeInstance`：树实例权威结构——枝干图（BranchNode 父子拓扑）
    + 体素反向索引（cell→branch_id，每个占位格唯一定位枝段）；
    **段分裂** `split_branch_at_cell`（首格断边/末格缩短/中间格
    分裂为 A+B）；根 BFS `find_supported`（无向遍历含分裂段）
  - `TreeGenerator`：确定性纯函数生成（同 seed 同结构）——模板化
    形态（垂直主干底粗顶细逐格半径、上部侧枝水平伸出再上翘、
    末梢+冠心叶球），无随机游走
- **渲染**：树干 = 独立合并网格（每树 1 MeshInstance3D + StaticBody3D
  简化碰撞，参照 DropManager 实体模式）；BRANCH_ID 是**纯占位**
  （无区块几何，射线/挖掘接口零改动）；树叶继续走区块方块网格
- **生命周期**：chunk 级引用计数（ChunkManager 两个可空 Callable
  钩子：`on_chunk_active_cb`/`on_chunk_unloaded_cb`）——影响范围
  ±TREE_REACH 首个 chunk 激活时建实体（确定性重放+应用砍伐记录），
  归零销毁；根列卸载但邻 chunk 活动时树存活
- **砍伐管线**：BRANCH 被挖 → TreeManager.on_branch_broken →
  split → BFS → 失支撑分量转 **RigidBody3D**（受控倒伏：绕切点
  向质心偏移方向、角速度 1.2 rad/s + 初速 0.3；gravity_scale
  = 24/9.8 与游戏手感一致）→ 叶格清除（set_block 走区块管线）→
  落地/5s 超时结算掉落物（log×格数/3 + stick）；保留树重建
  mesh/碰撞（revision++）；**砍主干 = 上部整树倒下、树桩保留**
- **存档**：world.json extra meta `"trees": {"algorithm":
  "treegen-v1", "events": [cut...]}`——加载按 `replay_only` 重放
  （跳过已 AIR 格、不重复奖励）；结构由种子重建，只存事件流
- **验证**：16 套件 11911 项 0 失败（含树系统 29 项单测）；
  砍树演示（capture_trees.tscn）：29 枝树砍主干 → 28 枝脱落
  刚体倒下 → 树桩保留 → 落地结算掉落物

## 阶段 E 实测数据（官方构建 / 2 核 / 调试构建，3 次取中位）

| 指标 | 实测 | 结论 |
| --- | --- | --- |
| 生成 | 13.8 ms/区块（16^3，v2 地形） | 后台线程可接受 |
| 面剔除网格（GDScript） | 9.1 ms/区块（192 区块 31,654 面） | 默认实现 |
| Greedy 网格（C#） | 28.7 ms/区块；面数与顶点均降至 **22.8%** | 较 GDScript 版快 2.4×（62→26 ms）；仍比面剔除慢，保留为开关 |
| 编辑重网格延迟 | 9.0 ms/区块（工作线程，面剔除路径） | 挖掘/放置手感即时 |
| 存档写/读 | 3.7 / 2.5 ms/区块（zstd + 原子写） | 卸载即存盘无压力 |
| 16^3 vs 32^3 | 同体积：生成 1411 vs 1819 ms，网格 1721 vs 1289 ms（面数相同） | 16^3 更优，维持候选值 |

贪心正确性由"四边形总面积 == 面剔除面数"不变量（单测，含真实地形）与
渲染回归检查共同保证；其 T 型交界在双面渲染下有个位像素级 z-fighting
（已计入检查容差并注明）。

## 决策记录

- **脚本语言 GDScript + C#**：逻辑层 GDScript；性能重灾区（Greedy 网格器）
  经阶段 E 基准验证后迁移 C#，按"算法重量"选择调度（§14，见下方决策）。
- **区块尺寸 16³**：候选值之一，写入 `WorldConfig`，非永久约束（§4.1）。
- **图集为程序化占位贴图**：逐 tile 固定种子生成，规避第三方许可证核验（§7.3）；
  真实材质包在阶段 E 通过同名 tile 体系接入。Nearest 过滤 + 关闭 mipmap 避免渗色（§7.1）。
- **网格边界策略**：y<0 视为实心（不渲染世界底面），其余越界视为空气（§6.4）。
- **同步生成**：Stage A 一次性构建固定 6x3x6 区块；后台线程与任务版本在阶段 C 引入（§10.1）。
- **三角形绕序**：Godot 光栅化的正面是"从面外侧看顺时针"（与 OpenGL 式逆时针假设相反）。
  曾因绕序相反导致所有面被背面剔除、可透视地形内部；`debug/render_check.tscn`
  以无光照白材质的像素统计客观回归此问题。
- **区块碰撞**：可见面剔除后的三角形直接转 ConcavePolygonShape3D（表面即碰撞面）；
  mesh_dirty 与 collision_dirty 分开标记、分开重建（§8.3）。Stage B 为同步整区块重建，
  局部更新/延迟合并按文档要求待测量后再做。
- **挖掘为计时生效**（物品层升级）：时长 = hardness / 工具速度；
  徒手/等级不足 4 倍减速且不掉落。掉落经地面实体拾取；
  工具耐久属后续玩法层。
- **物品身份与方块同名**（`core:stone` 既指方块也指其物品）：挖什么
  得什么、放什么消耗什么，映射零特判；纯物品（煤/镐）独立命名。
- **背包序列化用稳定名称**：与方块存档同一原则（§2.2），注册顺序
  变化不破档；未知名称跳过、超上限截断，旧档缺键补起始装备。
- **流式线程模型（§10.1）**：工作线程纯计算 + 主线程提交；过期任务用
  edit_serial 快照判定。网格与碰撞仍整区块重建（16^3 重建成本低），
  局部更新留待基准数据支持后再引入。
- **区块存档为完整数据而非生成增量（§9.1）**：体积略大但生成算法升级后
  旧存档仍精确还原（配合生成版本记录，§5.1）；调色板 + 稳定名称保证
  注册表重排安全（§2.2）。
- **玩家状态在 world.json**：位置/朝向/手持/出生点，自动与退出时保存。
- **生成算法 v2（阶段 E 扩充）**：沙地/砂岩地层 + 煤/铁矿脉。v1 存档
  读取时会告警"未修改区域将用新算法重建"，完整区块数据不受影响。
- **默认网格算法为面剔除**：贪心虽把顶点压到 22.8%，但即便 C# 加速后
  构建仍慢 3 倍（9.1 vs 28.7 ms/区块，§6.3 实测），收益不足以切换默认；
  两者共享正确性语义与测试。
- **掉落实体物理不依赖引擎物理服务器**：体素网格上的逐轴点碰撞
  （规则层纯函数化，headless 可精确断言落点/撞墙/冻结）。实体少了
  RigidBody 的 island/接触开销，且与体素 DDA 射线同一世界观——
  未加载区块按空气、y<0 实心，冻结门禁与玩家脚下区块检查一致。
- **掉落视觉模仿 BDIR 而非自创**：反编译该 Mod 的 Mixin 字节码核对
  行为（翻滚链 = pivotX(-90°)+pivotZ、落地冻结、散布偏移/整齐堆叠
  两种 count 渲染、默认转速 100），按其默认配置复刻；3D 迷你方块
  复用地形网格器的面表与绕序约定，不引入第二套几何规则。
  唯一偏离：落地姿态不沿用 Mod 的冻结倾角（立方体会以棱/角顶地），
  改为端正竖立、底面贴地，仅保留偏航角。
- **掉落持久化走 world.json 而非区块文件**：数量少、全局性（可跨
  区块移动）、与玩家状态同级；区块文件保持纯体素数据职责。
- **材质包许可证（§7.3）**：当前 Conquest 为用户提供的本地包，仅限
  个人使用、不可再分发；可商用的 CC0 / CC BY 4.0 备份组保留在
  `assets/textures/open_cc0_backup/`，发布前整体换回即可。
  来源、许可与下载日期记录于 assets/textures/CREDITS.md。
- **原生迁移（§14 决策记录，最终状态：C# 已落地，选择调度）**：
  snap 版 godot-4 曾阻断全部原生路径（C# 缺 Packed*Array 类型、godot-cpp
  镜像缺失、裸 GDExtension 接口全 void 返回）。改用官网 mono 构建后 C# 打通，
  遗留两个环境坑与解法：
  1) **.NET 运行时版本**：程序集面向 net8.0 而系统仅有 .NET 10，默认
     `LatestMinor` 不跨主版本导致运行时静默解析失败——csproj 设
     `RollForward=LatestMajor` 解决；
  2) **渲染器**：llvmpipe 的 Vulkan JIT 会生成 BMI2 指令，本机 2014 年
     赛扬不支持 → 编辑器 SIGILL 崩溃；项目锁 `gl_compatibility` 走
     GT 610 的 OpenGL 4.3 硬件加速。
  C# 侧用 Variant 批量互转（`AsInt32Array` 一次转整段，绕开缺失的
  Packed*Array 类型）。A/B 基准（192 区块）：**贪心 62.2→25.9 ms/区块
  （C# 胜 2.4×）；面剔除 12.9→29.3 ms（GDScript 胜 2.3×）**——算法重的
  路径 C# 收益盖过跨语言装箱开销，算法轻的反而吃亏。落地为**选择调度**：
  `GreedyMesher` 走 C#，`ChunkMesher`（默认路径）走 GDScript；
  `NativeMeshBridge` 保持中立供等价测试直调（5 世界 × 2 网格器 × 60 检查）。
  `VOXEL_NO_NATIVE=1` 可强制全 GDScript（A/B 与隔离用）。
